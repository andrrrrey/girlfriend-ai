# Отчёт: соответствие реализации платформы согласованному ТЗ

**Дата:** 2026-06-03
**Репозиторий:** girlfriend-ai (монорепо: `apps/{web,api,ai,worker,migrator}`, `packages/*`)
**Технологии:** Next.js (web), NestJS (api), Fastify + провайдеры AI (ai), BullMQ worker (worker), PostgreSQL/Prisma, Redis, S3.

## Резюме (TL;DR)

| Этап | Готовность | Комментарий |
|------|-----------|-------------|
| **Этап 1 — Пользовательский AI-MVP** | ✅ ~95–100% | Реализован полностью, включая реальные интеграции LLM/STT/TTS, стриминг, демо-лимиты, авто-очистку чатов. |
| **Этап 2 — Контент и публичная часть** | 🟡 ~85% | Реализовано почти всё; отклонения: видео — 2 из 3 режимов, черновики персонажа хранятся в браузере (localStorage), а не на сервере; wizard — 9 шагов вместо 8. |
| **Этап 3 — Управление и монетизация** | 🔴 ~20–25% | Админка частично; **модерация, жалобы, санкции, подписки Basic/Pro/Deluxe, checkout, webhooks, история платежей и страница «Премиум» — отсутствуют**. |

**Страницы (10 по ТЗ):** реализовано **8 из 10**. Отсутствуют: **Гайд** и **Премиум** (отдельной страницы нет — только вкладка-заглушка в профиле).

**Главный риск:** платёжной системы нет вообще — есть только UI-заглушки (`PremiumPopup` с комментарием `/* TODO: navigate to payment */`). Весь Этап 3 в части монетизации не выполнен.

**Сверх ТЗ:** дополнительно сделаны функции, которых не было в задании — подписки на пользователей (Follow), комментарии к персонажам, чат-профили, расширенный конструктор генерации (внешность/одежда/позы/локации/камера), мульти-провайдерный AI, авто-перевод промптов, публичный профиль автора и др. (см. раздел «Реализовано сверх ТЗ»).

| Язык (i18n) | 🟡 Частично | Поле `User.lang` хранится и меняется через API. Полноценная i18n-локализация фронтенда не подтверждена (хранится предпочтение, переключатель есть). |

| Действия с сообщениями: copy/delete/edit/regenerate | ✅ Готово | `DELETE`/`PATCH`/`/regenerate`/`/copy` (+ аудит копирования `MessageCopyAudit`); edit/regenerate каскадно удаляют последующие и дают новый ответ стримингом. |

## Этап 2 — Контент, генерации и публичная часть — 🟡 В основном готово

| Пункт ТЗ | Статус | Подтверждение |
|----------|--------|---------------|
| Персонажи: wizard 8 шагов, draft после каждого шага, JSONB | 🟡 Частично/Отклонение | `apps/web/app/create/page.tsx`: **9 шагов** (базовые параметры → происхождение → лицо → тело → характер → образ жизни → kinks → воспоминания → превью). JSONB-поле `Character.personality` — есть. **Черновик сохраняется в `localStorage` браузера** (`create_character_draft`), а не на сервере в виде draft-записи. Pre-moderation отсутствует (по ТЗ — корректно). |
| Генерация изображений (async) | ✅ Готово | `apps/api/src/generation` + `apps/worker/src/index.ts`: реальные провайдеры (SDXL, Flux, Juggernaut, Civitai), очередь BullMQ, поллинг статуса, авто-перевод кириллических промптов. |
| Генерация видео (3 режима, async) | 🟡 Частично | Определены 3 режима: `scratch` (текст→видео) ✅, `img2vid` (изображение→видео) ✅, **`continue` (видео→видео) — отключён** (`generation.controller.ts` бросает NOT_IMPLEMENTED; комментарий: «задачи падают и жгут ресурсы»). Итог: **2 из 3 режимов**. |
| Медиатека пользователя + bulk-операции | ✅ Готово | `apps/web/app/my-ai/page.tsx`: режим управления, мультивыбор, групповое удаление; `apps/api/src/media` — загрузка в S3, signed-url. |
| Home, Shorts, Публичная галерея (feeds, фильтры, new/popular) | ✅ Готово | `page.tsx` (Home), `shorts/page.tsx` (вертикальная лента, авто-плей), `gallery/page.tsx`. Фильтры: пол, стиль, тип; сортировки: новые/популярные/старые/имя. |
| Лайки | ✅ Готово | `apps/api/src/likes`: полиморфные лайки (`Like`), toggle/status/count/batch/my; компонент `LikeButton` на карточках, в галерее и shorts. |

**Отклонения от ТЗ по Этапу 2:**
1. Видео: режим `continue` не работает (отключён) → **2/3 режимов**.
2. Черновики персонажа: реализованы как localStorage-черновик в браузере, а не серверный draft «после каждого шага» (как буквально в ТЗ). Потеря при смене устройства/браузера.
3. Wizard: **9 шагов вместо 8** (это «больше», но формально отличается от ТЗ — стоит сверить с заказчиком, какой набор шагов считать целевым).

## Этап 3 — Управление и монетизация — 🔴 Выполнено частично/минимально

| Пункт ТЗ | Статус | Подтверждение |
|----------|--------|---------------|
| Админка MVP: пользователи, контент, жалобы | 🟡 Частично | `apps/api/src/admin` + `apps/web/app/admin`: управление пользователями (список, поиск, смена роли/подписки), CRUD персонажей, настройки API-ключей, просмотр генераций, страница costs (стоимость), каталоги опций генерации. **Раздела «жалобы» нет.** |
| Модерация: approve/reject, базовые санкции | 🔴 Отсутствует | В схеме нет моделей `Report`/`Complaint`/`Moderation`/`Ban`. У `Comment`/`Character` нет статусов модерации; у `User` нет флагов бан/блок. Эндпоинтов approve/reject и санкций нет. |
| Жалобы (reactive moderation) — из «Предмета задания» | 🔴 Отсутствует | Функционала подачи жалоб (на контент/пользователей) в коде нет. |
| Аналитика: ключевые события и воронки | 🟡 Частично | Есть `UsageLog`/`UsageCounter` (действия, токены) и дашборд costs. **Нет таблицы событий, воронок, конверсий.** |
| Подписки Basic / Pro / Deluxe | 🔴 Отсутствует | В БД только строковое поле `User.subscription` (`free`/платно). **Тарифов Basic/Pro/Deluxe нет**, модели `Subscription` нет, срока действия нет. |
| Paywall и entitlements на backend | 🟡 Частично | Бэкенд жёстко применяет лимиты free-тарифа (`DemoService`); на фронте `PremiumPopup`. **Полноценной системы entitlements, привязанной к оплате/тарифу, нет.** |
| Checkout + webhooks (активация/отмена/продление) | 🔴 Отсутствует | **Нет ни одной платёжной интеграции** (Stripe и т.п.), нет webhook-эндпоинтов, нет моделей платежей. Кнопки оплаты — нерабочие заглушки (`/* TODO: navigate to payment */`). |
| История платежей + страница «Премиум» | 🔴 Отсутствует | Страницы `/premium` нет (только вкладка-заглушка в профиле). Истории платежей и модели транзакций нет. |

**Итог Этапа 3:** управляемость частичная (базовая админка есть), но **экономика продукта не реализована**: ни подписок по тарифам, ни оплаты, ни webhooks, ни истории платежей, ни модерации/жалоб/санкций.

## Реализовано СВЕРХ ТЗ (бонусный функционал)

В ходе разработки добавлены функции, которых нет в ТЗ, — фактически выполнено больше согласованного объёма:

| Функция | Где | Описание |
|---------|-----|----------|
| **Подписки на пользователей (Follow)** | `apps/api/src/users` (`Follow`), `POST/DELETE /users/:nickname/follow` | Социальный граф «подписчики/подписки» — в ТЗ не значился (там только лайки). |
| **Комментарии к персонажам** | `apps/api/src/comments` (`Comment`), CRUD + count | Полноценные комментарии; в ТЗ для публичной части были только лайки и жалобы. |
| **Чат-профили пользователя** | `apps/api/src/chat-profiles` (`ChatProfile`), CRUD | Пользовательские «персоны/описания себя» для контекста чата — сверх ТЗ. |
| **Расширенный конструктор генерации изображений** | `CharacterOption`, `AppearanceCategory/Option`, `PoseCategory/Option`, `SceneCategory/Option`, `CameraOption` + admin-страницы | Богатые каталоги опций (внешность, одежда, позы, локации, ракурс камеры, кадрирование) с превью и промптами — далеко за рамками «генерация изображений». |
| **Несколько AI-провайдеров с выбором модели** | `apps/ai/src/index.ts` | ModelsLab + AtlasCloud + Civitai, выбор моделей (SDXL, Flux, Juggernaut, llama-3 и др.). ТЗ требовал лишь работающую генерацию. |
| **Авто-перевод кириллических промптов** | `apps/api/src/generation` | Детект кириллицы и перевод в EN перед отправкой провайдеру. |
| **Публичный профиль пользователя** | `apps/web/app/users/[nickname]` | Отдельная страница профиля автора (сверх 10 страниц ТЗ). |
| **Аудит копирования сообщений** | `MessageCopyAudit` | Логирование событий копирования AI-сообщений. |
| **Соц-ссылки в профиле** | `SocialLink` (VK/Instagram/X) | Внешние ссылки на профиле. |
| **CAPTCHA (Turnstile)** | `apps/api/src/auth` | Защита регистрации/логина — в ТЗ не оговаривалась. |
| **Дашборд стоимости генераций** | `apps/web/app/admin/costs` | Расчёт затрат по моделям изображений/видео. |
| **S3 thumbnails / signed URLs** | `imageThumbKey`/`imageFullKey`, `apps/api/src/s3` | Превью и подписанные URL для медиа. |

> Примечание: часть «бонусов» (комментарии, подписки) усиливает необходимость **модерации**, которой пока нет (см. Этап 3).
